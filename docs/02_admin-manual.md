# 管理者向け運用マニュアル

合同会社シュガーラッシュの会員サービスを運営するための手順です。

- 第1章：申込みからレポート納品までの流れ（毎回の業務）
- 第2章：会員の管理（期限延長・パスワード再発行・停止）
- 第3章：レポートの作り方
- 第4章：サイトの内容を更新する
- 第5章：準備（はじめに一度だけ）
- 第6章：データの管理と注意事項
- 付録：メール文例

---

## 第1章　申込みからレポート納品までの流れ

申込みの状態は、次の3段階を区別して管理します。`docs/application-ledger.csv` を Excel や Google スプレッドシートで開き、1件1行で記録してください。

| 状態 | 意味 | 会員ページ |
|---|---|---|
| 申込受付 | フォームから申込みが届いた | 使えない |
| 入金確認 | 振込を通帳・ネットバンキングで確認した | 使えない |
| 会員権限付与 | 会員IDを発行し、メールで送った | 使える |

### 1-1　申込みを受け付ける（状態：申込受付）

1. フォームの通知メール、または Netlify の「Forms」→「contact」で内容を確認します。お問い合わせ種別が「サービスのお申込み」のものが申込みです。
2. 台帳に1行追加します（受付日、申込ID〔例 A2026-001〕、お名前、メール、プラン、金額、状態＝申込受付）。
3. 付録の「文例1：受付・お振込のご案内」で返信します。お振込先と金額、支払期限を記載します。
   - プランが未選択・不明な場合は、先に確認のメールを送ります。

### 1-2　入金を確認する（状態：入金確認）

1. 通帳・ネットバンキングで、振込名義・金額・日付を確認します。
2. 台帳の「入金確認日」「振込名義」を記入し、状態を「入金確認」にします。
3. 名義が違う・金額が足りないなど不明な点があれば、会員IDを発行する前にメールで確認します。

> **入金を確認する前に会員IDを発行しないでください。** 会員権限は入金確認後に付与する、という運用をサイトに掲載しています。

### 1-3　会員IDを発行する（状態：会員権限付与）

1. 会員IDを決めます。台帳の続き番号で `SR0001`、`SR0002`… のように付けます（半角英大文字・数字・ハイフン）。
2. 第5章の準備をしたパソコンで、次のコマンドを実行します。

```bash
npm run member -- create --id SR0001 --name "山田" --plan standard
```

- `--plan` は `basic`（ベーシック）／`standard`（スタンダード）／`p90`（90日継続）。
- `--name` は会員ページ上部に「山田 さん」と表示される名前です（姓だけでも可）。
- 利用開始日は実行した日（日本時間）になり、終了日はプランの日数から自動で計算されます。開始日を指定したい場合は `--start 2026-11-01` を付けます。

3. 画面に**初期パスワード**が表示されます。この画面でしか表示されないので、すぐに「文例2：会員情報のお知らせ」に貼り付けて送信します。パスワードをメモ帳などに保存しないでください。
4. 台帳に会員ID、利用開始日・終了日を記入し、状態を「会員権限付与」にします。

### 1-4　記録の提出を確認する（スタンダード・90日継続）

会員が会員ページから記録を提出すると、Netlify Blobs の `submissions` に保存されます（通知メールは届きません。週に1〜2回、確認してください）。

```bash
npm run submissions -- list                 # すべての提出を一覧表示
npm run submissions -- list --id SR0001     # 特定の会員だけ
npm run submissions -- download --id SR0001 --out ./submissions   # 写真・PDFと入力内容を保存
```

保存されたフォルダには、写真・PDF と、入力欄の内容（`.json`、メモ帳で開けます）が入っています。
**レポートを作り終えたら、パソコンに保存したファイルは削除してください。**

提出に病名・服薬など医療に関する情報が含まれていた場合は、その部分をレポートに使わず、本人に一言お知らせしたうえで削除します（プライバシーポリシー第4項）。

### 1-5　レポートを作って掲載する

1. 第3章の手順でレポートのPDFを作ります。
2. 次のコマンドで、その会員のページに掲載します。

```bash
npm run report -- upload --id SR0001 --file ./SR0001_2026-11.pdf --title "2026年11月 月間振り返りレポート" --name 2026-11-monthly
```

- `--name` は会員ページのURLに使われる名前です（半角英数字とハイフン）。同じ名前で再度アップロードすると差し替えになります。
3. 会員ページの「個別レポート」に表示されます。「文例3：レポート掲載のお知らせ」でお知らせし、台帳に納品日を記入します。

掲載済みの確認・削除：

```bash
npm run report -- list --id SR0001
npm run report -- delete --id SR0001 --name 2026-11-monthly
```

> レポートは会員IDごとに分けて保存され、会員ページではログインしている本人の分しか表示・取得できない仕組みです。**`--id` の指定を間違えると別の会員に掲載されてしまう**ので、実行前に必ず確認してください。

## 第2章　会員の管理

### 2-0　ログインの2つの方法

| 方法 | 使えるもの | 管理方法 |
|---|---|---|
| 共通パスワード（会員IDは空欄） | 会員限定記事・記録シート | 初期値は `edge-lib/shared-default.mjs`（変更：`npm run shared-password -- 新しいパスワード` → コミット）。Netlify の環境変数 `MEMBER_PASSWORD` を設定するとそちらが優先。変更すると全員ログアウト |
| 会員ID＋個別パスワード | 上記に加え、記録提出・個別レポート・利用期限の管理 | 下記の `npm run member` コマンド（`SESSION_SECRET` の設定が必要） |

ベーシックプランの方には共通パスワードのみ、スタンダード・90日継続プランの方には会員IDと個別パスワードをお送りする、という使い分けができます。共通パスワードには利用期限がないため、期間終了後も見られる状態を避けたい場合は、定期的にパスワードを変更して、利用中の方にだけ新しいパスワードをお知らせしてください。


```bash
npm run member -- list                                  # 全会員の一覧（ID・プラン・期間・状態）
npm run member -- show --id SR0001                      # 1人の詳細
npm run member -- extend --id SR0001 --end 2026-12-31   # 利用期限の変更
npm run member -- reset-password --id SR0001            # パスワード再発行（新しいパスワードが表示されます）
npm run member -- suspend --id SR0001                   # 利用停止（すぐにログアウトされます）
npm run member -- activate --id SR0001                  # 停止の解除
npm run member -- delete --id SR0001                    # 会員情報の削除
```

- **パスワードを忘れた**との連絡：ご本人のメールアドレスからの連絡であることを確認し、`reset-password` で再発行して返信します。
- **パスワード再発行・停止をすると、その会員のログイン状態はすべて無効になります**（別の端末でログインしたままの場合も含む）。会員情報が他人に知られたおそれがあるときもこの操作をします。
- **利用期限**：終了日を過ぎると記事・シート・提出は使えなくなります。作成済みのレポートは、終了日から30日間だけダウンロードできます（この日数は `src/content/site.mjs` の `reportGraceDays`）。
- **ログインできない**との連絡：同じ会員IDで5回続けて間違えると15分間ロックされます。15分待ってから試すよう案内してください。それでもだめなら `show` で期間と状態を確認します。

## 第3章　レポートの作り方

レポートは `tools/report-maker/report.html`（レポート作成ツール）で作ります。サイトには公開されない、管理者のパソコンで使うツールです。インターネット接続は不要です。

### 3-1　記録データを作る

入力例として `tools/report-maker/sample-monthly.json`（月間）と `sample-90days.json`（90日総括）があります。これをコピーして、会員の記録に書き換えます。テキストエディタ（Windows はメモ帳、Mac はテキストエディット）で開けます。

**月間レポート（`"type": "monthly"`）の項目**

| 項目 | 内容 |
|---|---|
| `sample` | **本番では必ず `false`**（`true` だと「架空サンプル」と表示されます） |
| `title` | 「月間振り返りレポート」など |
| `round` | 何回目か（"1"〜"3"） |
| `memberName` / `memberId` / `plan` | お名前・会員ID・プラン名 |
| `periodStart` / `periodEnd` / `issued` | 対象期間・発行日（`2026-11-01` の形式） |
| `days` | 1日ごとの記録（下表）。記録シートの1行を1件として、日数分並べます |
| `text` | 文章（`trend` 傾向、`continued` 継続できた取り組み、`nextItems` 次月の振り返り項目、`summary` まとめ） |

`days` の1件：

| 項目 | 書き方 |
|---|---|
| `d` | 日付 `"2026-11-01"` |
| `recorded` | その日に記録があれば `true`、なければ `false`（`false` の日は他の項目不要） |
| `wake` / `bed` | 起床（その日の朝）・就寝（その日の夜）の時刻 `"6:40"` `"23:30"`。空欄なら書かない |
| `wakeFeel` | 目覚め `"◎"` `"○"` `"△"` |
| `meals` | 食事をとったか `{"b": true, "l": true, "d": false}`（b 朝・l 昼・d 夕。「—」は `false`、空欄は項目ごと書かない） |
| `balance` | 主食・主菜・副菜がいくつそろったか `{"b": 1, "l": 3, "d": 2}` |
| `steps` | 歩数（数字）。測っていない日は書かない |
| `exercise` | 意識して運動した日は `true` |
| `careAM` / `carePM` | `"✓"` `"△"` `"—"` |

文章の中に `{{recorded}}`（記録した日数）、`{{wakeGood}}`（目覚め◎の日数）、`{{careAM}}`、`{{exDays}}`、`{{bfSkip}}`、`{{avgBed}}`、`{{avgWake}}`、`{{avgSteps}}` などを書くと、集計した数字に自動で置き換わります。

**90日総括（`"type": "total90"`）** は、`months` に3か月分（`label`、`periodStart`、`periodEnd`、`days`、`reportNote`）を並べ、`text` に `overview`、`continued`、`trends`、`goals`、`summary` を書きます。

### 3-2　文章を書くときの決まり

レポートは「記録の整理」であり、診断・指導ではありません。次を守ってください。

- 書くのは**記録から数えられる事実と、そこから言える傾向**だけ。「〜が記録されています」「〜の傾向が見られます」の形で書く。
- 書かないこと：病気や健康状態の判断（「睡眠不足です」「〜の可能性があります」）、減量・食事制限・運動量の指示、医療機関の受診先の指定、効果の約束（「続ければ痩せます」）、記録されていないことの推測。
- 次月の項目は「候補」として示し、決めるのは本人であることを明記する。
- 体調への不安が読み取れる記述があった場合は、「医療機関にご相談ください」と添えるにとどめる。

### 3-3　PDFにする

1. `report.html` を Chrome で開きます。
2. 右上の入力欄に、作ったJSONの中身をすべて貼り付けて「表示」を押します（エラーが出たら、カンマや「"」の抜けを確認）。
3. 内容・グラフ・会員名・期間を確認します。**「架空サンプル」の帯が出ていないこと**（`"sample": false`）を必ず確認してください。
4. 「印刷・PDF保存」→ 送信先「PDFに保存」、用紙サイズ A4、余白「なし」、「背景のグラフィック」にチェック →「保存」。
5. ファイル名は `SR0001_2026-11.pdf` のように会員IDを含めます。

## 第4章　サイトの内容を更新する

GitHub 上でファイルを編集して「Commit changes」すると、数分で自動的に公開されます。

### 4-1　会社情報・料金・運用条件

`src/content/site.mjs` を編集します。会社概要・フッター・特定商取引法に基づく表記・料金表・FAQ など、関係するすべてのページに反映されます。

- `company.corporateNumberConfirmed`：法人番号を国税庁法人番号公表サイトや登記事項証明書で照合したら `true`。
- `terms` の各項目：正式な運用条件を決めたら文章を修正し、`confirmed: true` にします。`false` の項目があると、ビルドのたびに警告が表示されます。
- `plans`：料金・提供内容。変更する場合は、利用規約・特定商取引法の表記との整合性も確認してください。
- `site.url`：独自ドメインに変更したら修正。
- 規約・プライバシーポリシーの制定日は `scripts/pages-legal.mjs` の `LEGAL_DATE`。

### 4-2　記事の追加・修正

- 公開記事：`src/content/free/`、会員限定記事：`src/content/members/` の `.md` ファイル。
- 新しい記事は、既存のファイルをコピーして書き換えるのが確実です。会員記事のファイル名は `article-41.md` のように番号順にします。
- 会員記事の本文中の「記事12」のような表記は、該当する記事へのリンクにすると便利です：`[記事12](/members/articles/article-12/)`
- 記事の写真はカテゴリごとに自動で表示されます（`scripts/build.mjs` の `FREE_PHOTO`・`MEMBER_PHOTO`、画像は `src/static/img/photos/`）。

ファイルの先頭（`---` で囲まれた部分）：

| 項目 | 内容 |
|---|---|
| `slug` | URL になる名前（半角小文字英数字とハイフン。全記事で重複不可） |
| `title` / `summary` | タイトル・概要（一覧に表示） |
| `category` | 公開記事のみ：`beauty` 美容習慣／`food` 食生活／`sleep` 睡眠／`exercise` 運動／`selfcare` セルフケア／`rhythm` 生活リズム |
| `date` | 公開記事のみ：公開日 `2026-11-01` |
| `order` | 会員記事のみ：記事番号（1〜40。一覧の並び順と「記事N」のリンクに使用） |
| `category`（会員記事） | `beauty` 美容・エイジングケア／`body` 体型管理／`food` 食生活／`sleep` 睡眠・休息／`movement` 運動・身体活動／`selfcare` セルフケア／`habit` 生活習慣記録／`program` 継続プログラム（名称や並びは `src/content/members/_meta.json`） |
| `tool` | 関連する記録ツール：`guide` `check` `sheet30` `sheet90` `sleep` `food` `review` `goals` `plan90` |
| `refs` | 参考資料（任意）。`  - 資料名｜発行元｜URL` の形で1行ずつ |

本文：`## 見出し`、表は `| 項目 | 内容 |` の形式（2行目に `|---|---|`）、チェックリストは `- [ ] 項目`、`### 小見出し`、`- 箇条書き`、`1. 番号付き`、`**強調**`、`[リンク文字](URL)`。最初の `##` より前の段落が導入文になります。読了時間は文字数から自動計算されます。

**記事を書くときの決まり**：効果を断定しない／根拠を確認できない数値や研究結果を書かない／公的機関の資料を参照したら `refs` に記載し、リンク先が開けることを確認する／医療の判断が必要な話題は「医療機関に相談」と案内する。

### 4-3　記録ツール（PDF）の差し替え

`protected/tools/` の同じ名前のPDFを置き換えてコミットします（このフォルダは公開されず、会員ページからのみダウンロードできます）。新しいツールを増やす場合は、PDFを置いたうえで `src/content/site.mjs` の `tools` に1件追加します。
シートのデザインを作り直す場合は `tools/pdf-src/make_assets.py` を使います（開発者向け。Python と Playwright が必要です）。

### 4-4　更新がうまくいかないとき

Netlify の「Deploys」で失敗（Failed）になっていたら、ログの赤い行を確認します。多いのは次の原因です。

- 記事の先頭の `---` の書き方の誤り、`slug` の重複、存在しない `tool` や `category` の指定（ログに該当ファイル名が表示されます）
- `protected/tools/` のPDFを消した・名前を変えた

## 第5章　準備（はじめに一度だけ）

管理用コマンドを使うパソコンの準備です。

1. Node.js 20 以上をインストール（nodejs.org の「LTS」版）。
2. GitHub Desktop などでリポジトリをパソコンに取得。
3. ターミナル（Windows は PowerShell）でそのフォルダに移動し、`npm install` を実行。
4. 作業のたびに `NETLIFY_SITE_ID` と `NETLIFY_AUTH_TOKEN` を設定（`docs/03_netlify-settings.md` 第6節）。
5. 動作確認：`npm run member -- list` で「登録された会員はいません」と表示されれば準備完了です。

（開発者向け）`npm run build` でサイトを生成、続けて `npm test` で認証の自動テスト（35項目）を実行できます。

## 第6章　データの管理と注意事項

- **保存期間**：プライバシーポリシーで「利用期間の終了日から1年後に削除」と定めています。月に1回、台帳で該当する会員を確認し、次を実行してください。

```bash
npm run report -- list --id SR0001        # 掲載中のレポートを確認
npm run report -- delete --id SR0001 --name （レポート名）
npm run submissions -- delete --id SR0001
npm run member -- delete --id SR0001
```

- **共有しない**：会員のパスワード、`SESSION_SECRET`、`NETLIFY_AUTH_TOKEN` は、メール・チャット・GitHub に書かないでください。
- **パソコンに残さない**：ダウンロードした提出記録・作成したレポートのPDFは、掲載後に削除するか、パスワードをかけた場所で保管してください。
- **台帳**：申込管理台帳は個人情報を含みます。共有設定に注意し、GitHub には入れないでください（`docs/application-ledger.csv` は空のひな形です）。
- **表現**：サイト・記事・レポート・メールのいずれでも、効果の保証、診断や指導と受け取られる表現、創作した利用者の声・実績・数値を使わないでください。

>
> ○○ 様

>
> ・お申込みプラン：スタンダードプラン（30日間）
> ・ご請求金額：9,800円（税込）
> ・お支払期限：○月○日（○）
>
> 【お振込先】
> （銀行名・支店名・口座種別・口座番号・口座名義）
>

>

### 文例2：会員情報のお知らせ

>
> ○○ 様
>
> ご入金を確認いたしました。ありがとうございます。
